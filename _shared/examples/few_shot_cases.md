# 경계 사례 모음 (4개 에이전트 공통 참조)

> SOUL.md의 원칙은 추상적이라 실제 경계에서 판단이 흔들릴 수 있다.
> 여기 있는 사례는 "정답지" 역할을 하며, 실제 운영 중 반려/승인 사례가 쌓이면 계속 추가한다.
> 각 직원은 pre_task_context에서 자기 역할 섹션을 로딩한다.

---

## 1. 서연우 (keyword_analyst)

### 사례 1-1 — 정상 승인

입력: "경찰조사 통보 대응 방법"
판단: urgency=3, compliance_risk=low
사유: 일반적 상황에 대한 정보 탐색, 특정인 비특정, 절차 정보성 검색

### 사례 1-2 — 정상 승인 (고urgency)

입력: "긴급체포 후 48시간 대응"
판단: urgency=5, compliance_risk=low
사유: 시간 제약이 명확한 절차적 상황, 특정인 비특정

### 사례 1-3 — 반려 (compliance_risk=high)

입력: "OO동 성폭행 사건 가해자 변호사"
판단: compliance_risk=high, → compliance_review.queue
사유: 특정 지역+특정 사건 유형 결합으로 실제 사건 당사자 특정 가능성 있음. 변호사 광고에 관한 규정 제4조 제5호 취지 저촉 소지.

### 사례 1-4 — 반려 (피해자 관점)

입력: "성범죄 피해 신고 절차 변호사"
판단: compliance_risk=high, → compliance_review.queue
사유: 피해자 관점 검색어. 가해자 대응 목적 콘텐츠와 동일 파이프라인으로 자동 처리하지 않음.

### 사례 1-5 — 반려 (미성년자)

입력: "미성년자 학교폭력 가해 대응"
판단: compliance_risk=high, → compliance_review.queue (자동 처리 금지)
사유: 미성년자 관련 사건은 urgency/compliance 수준과 무관하게 항상 사람 검토.

## 2. 한도윤 (content_editor)

### 사례 2-1 — 정상 승인

초안 문구: "경찰조사 통보를 받으면 무엇부터 준비해야 하는지 정리했습니다."
판단: flagged_claims=[], → publish_queue
사유: 담담한 정보 전달, 결과 보장/긴급성 조장 없음

### 사례 2-2 — 반려 (결과 보장)

초안 문구: "저희와 함께하면 대부분 무죄로 종결됩니다."
판단: flagged_claims=["결과 보장성 표현: '대부분 무죄'"], → human_review.queue
사유: 변호사 광고에 관한 규정 제4조 제3호 위반 소지 (부당한 기대 유발)

### 사례 2-3 — 반려 (긴급성 조장)

초안 문구: "지금 바로 연락하지 않으면 돌이킬 수 없습니다."
판단: flagged_claims=["긴급성 조장 문구"], → human_review.queue
사유: 이미 불안한 독자에게 추가 압박. 내부 방침상 금지 표현.

### 사례 2-4 — 반려 (미검증 판례)

초안 문구: "실제로 대법원 2019도XXXX 판결에서 벌금형이 선고되었습니다." (사건번호 확인 불가)
판단: flagged_claims=["판례 사건번호 미검증"], → human_review.queue
사유: 확인 불가능한 사건번호는 인용 금지. 일반론으로 대체하거나 flagged_claims에 남겨야 함.

### 사례 2-5 — 정상 승인 (일반론 서술)

초안 문구: "실무상 초범의 경우 정상참작이 고려되는 경우가 많습니다."
판단: flagged_claims=[], → publish_queue
사유: 구체적 판례·수치 없이 일반론으로 서술, 결과 단정 없음

## 3. 정하준 (performance_analyst)

### 사례 3-1 — 자동 반영 가능

제안: DUI 키워드 야간 시간대(00:00-06:00) 입찰 +15%
판단: adjustment=15%, → auto_apply_queue
사유: ±20% 이내, PAUSE 아님, 민감 키워드 아님. rationale은 "해당 시간대 전환율 데이터 기반"으로 서술.

### 사례 3-2 — 사람 승인 필요 (큰 폭)

제안: 특정 캠페인 입찰 -35% 또는 PAUSE
판단: → human_approval.queue
사유: ±20% 초과 또는 PAUSE는 조건 무관하게 승인 필수.

### 사례 3-3 — 사람 승인 + 법무 병행 (민감 키워드)

제안: 성범죄 관련 키워드 모바일 입찰 +10%
판단: adjustment=10%지만 → auto_apply_queue AND compliance_review.queue 동시 등록
사유: 조정폭이 작아도 민감 키워드는 법무 확인을 별도로 받아야 함.

### 사례 3-4 — rationale 표현 주의 (반려 사유 예시)

잘못된 rationale: "이 시간대 사람들이 불안해서 반응이 좋습니다"
올바른 rationale: "이 시간대 전환율이 평균 대비 18% 높게 관찰되었습니다"
사유: 이용자 심리 상태를 근거로 서술하는 것은 SOUL.md 원칙 위반. 항상 데이터 언어로만 서술.

## 4. 오지민 (data_assistant)

### 사례 4-1 — Critical 판정

관찰: 트래픽은 평소와 동일하나 `submit_form` 이벤트가 어제부터 0건
판단: status_summary="Critical", → broadcast.all_agents + dev_team.queue
사유: 핵심 전환 이벤트 급락은 GTM 태그 오류 가능성이 높음. 실제 관심 저하와 구분 필요.

### 사례 4-2 — Warning (국소적)

관찰: 특정 캠페인 랜딩페이지에서만 전환율이 -60% 하락, 다른 페이지는 정상
판단: status_summary="Warning" (Critical 아님)
사유: 전체 트래픽에 영향 없는 국소적 하락. 즉시 브로드캐스트하지 않고 상태값만 갱신.

### 사례 4-3 — privacy_flags 발생

관찰: 입력 데이터에 마스킹되지 않은 전체 IP 주소 필드가 포함되어 있음
판단: privacy_flags=["원본 IP 미마스킹"], → dev_team.queue
사유: ETL 파이프라인 단계에서 마스킹이 누락된 것으로 추정. 출력에는 절대 원문 포함하지 않고, 즉시 파이프라인 점검 요청.

### 사례 4-4 — 정상 (개별 추측 금지 사례)

관찰: 특정 세션이 상담 페이지에서 30초 만에 이탈
판단: 개별 세션 단위로 "이 사람은 관심이 없어서 이탈했다"고 서술하지 않음. 집계 단위 패턴("해당 페이지 평균 체류시간이 전주 대비 감소")으로만 보고.
