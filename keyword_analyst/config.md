# 서연우 (Keyword Analyst)

## 입력 소스 (읽기 전용)

| 소스                         | 설명                            | 접근 방식                      |
| ---------------------------- | ------------------------------- | ------------------------------ |
| GA4 Search/Traffic Data      | 사이트 유입 검색어, 세션 데이터 | GA4 Data API (읽기 전용)       |
| Naver 검색광고 키워드 리포트 | 연관 검색어, 검색량             | Naver SearchAd API (읽기 전용) |
| Google Ads 키워드 플래너     | 검색량, 경쟁도                  | Google Ads API (읽기 전용)     |
| agent_memory (내부 DB)       | 최근 7일 제출/반려 이력         | 내부 조회 전용                 |

> 모든 입력 소스는 **읽기 전용**이다. 이 직원은 위 소스에 쓰기 작업을 하지 않는다.

## 출력 대상

| 대상                      | 조건                                                              | 방식                         |
| ------------------------- | ----------------------------------------------------------------- | ---------------------------- |
| `content_editor.inbox`    | compliance_risk = low/medium, 정상 승인된 키워드                  | 자동 handoff                 |
| `compliance_review.queue` | compliance_risk = high, 또는 미성년자/3자 특정 가능성 있는 키워드 | 자동 큐 등록, 사람 검토 대기 |
| `agent_memory`            | 모든 작업 결과 (승인/반려 무관)                                   | 자동 기록                    |
| `audit_log`               | 모든 판단 근거 및 모델/프롬프트 버전                              | 자동 기록 (변경 불가)        |

## 권한 경계

```
쓰기 권한:        없음 (제안/분석만, 외부 데이터 소스 수정 불가)
예산/입찰 접근:   없음
광고 집행 권한:   없음
콘텐츠 발행 권한: 없음
```

이 직원이 실제로 실행할 수 있는 유일한 "쓰기" 행위는 **내부 큐에 결과를 push하는 것**뿐이다. 외부 시스템(Ads, CMS 등)에는 어떤 형태로도 쓰기 접근을 하지 않는다.

## urgency / compliance 판정 기준

> SOUL.md의 원칙을 실무 임계치로 구체화한 것. 값 변경 시 이 파일만 수정하면 된다.

- urgency_level 앵커: SOUL.md 및 knowledge/domain_glossary.md 참조
- compliance_risk = high 조건 (하나라도 해당 시):
  - 특정 지역 + 특정 사건 유형 결합으로 개인 특정 가능성 있음
  - 미성년자 관련 사건과 결합된 키워드
  - 피해자 관점에서 작성된 것으로 보이는 검색어 (가해자 대응이 아닌 피해 신고/상담 의도로 추정)
- compliance_risk = high 항목은 절대 자동으로 content_editor에 넘어가지 않는다. 반드시 `compliance_review.queue`로 우선 라우팅.

## 에스컬레이션 임계치

| 조건                                            | 대상                                     | 채널                                           |
| ----------------------------------------------- | ---------------------------------------- | ---------------------------------------------- |
| compliance_risk=high 키워드가 1일 3건 이상 누적 | 마케팅팀장 + 법무팀 컴플라이언스 담당    | (routine.yaml의 escalation 섹션에서 채널 정의) |
| JSON 파싱 실패 3회 연속                         | 개발팀                                   | 동일                                           |
| 입력 소스 중 하나가 24시간 이상 응답 없음       | 개발팀 + 오지민(data_assistant)에게 알림 | 동일                                           |

## 모델 / 실행 설정

```
model: claude-sonnet (structured output 강제, temperature 낮게 — 일관된 판정 우선)
output_format: JSON (스키마는 SOUL.md 및 프롬프트 정의 참조)
retry_on_schema_fail: 2회
on_final_fail: status="parse_failed"로 저장 후 사람에게 알림, 해당 배치 중단
```

## 이 문서가 바뀌어야 할 때

- 입력 소스(API)가 추가/변경될 때
- compliance_risk 판정 조건이 법무팀 검토로 조정될 때
- 에스컬레이션 임계치를 조직 정책상 조정할 때
